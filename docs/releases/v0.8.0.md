## intentplane 0.8.0: a sidecar for agent hosts, and no write outside the receipts

**A sidecar for agent hosts.** `python -m intentplane.sidecar` serves one agent host running many tasks at once,
such as DeepSeek Harness's `dsh-superagent`: the host issues one mandate per task, the task's tools propose actions
with it, and the GitHub pack decides (`pr.create`, `pr.comment`, `pr.merge`, and now `branch.push`). See
[docs/sidecar.md](../sidecar.md).

**`branch.push` through the gateway.** Publishing a task's branch was the one write a host did itself. It is now a
decided action with a receipt: the branch comes from the mandate, the commit is fetched from the host's read-only
mirror into the sidecar's own repository (the mirror's configuration and hooks play no part), it must fast-forward
the branch (there is no force push to ask for), and a commit that changes CI configuration waits for the operator.
The sidecar pushes with its own identity.

**A person's withdrawal is final.** `DELETE /v1/mandates/{task}` with `{"hold": true}` holds the task: no new
mandate (HTTP 409) until `POST /v1/mandates/{task}/release`, across restarts (`[sidecar] holds`). A call with a
withdrawn mandate is refused at its own stage, `withdrawn`, so a host knows not to issue again; expired mandates
and restarts still answer `authn`. Both events are receipts.

**Secrets in free text (defence in depth).** `forbid-text-with-secret` refuses a comment or PR whose title or body
looks like it carries a credential (known token formats, long high-entropy strings; `intentplane.textscan`). A
heuristic: a split or encoded secret passes, and some legitimate text does not.

**No CI secrets for the agent's code.** `branch.push` is refused while a workflow of the commit would run the task's
branch with a repository secret (`forbid-push-ci-exposes-secrets`): its tests and build scripts would run with it.
A job kept off task branches by its `if:`, or a workflow that does not run for them, is fine.

**Dependencies wait for the operator.** A commit that changes a manifest, a lockfile or a registry configuration
(`package.json`, `pnpm-lock.yaml`, `requirements*.txt`, `.npmrc`, `go.mod`, ...) is pushed only once the operator
confirms it, as a change to CI is.

**Reviews that count.** An approval counts only from a person with write access who is not the PR's author, not a
bot, and not one of the agents' accounts (`[github] not_reviewers`).

**Agent instructions wait for the operator.** A commit that changes `AGENTS.md` or another file agents read as
instructions on every task is pushed only once the operator confirms it.

**Short-lived GitHub tokens.** `GH_TOKEN_FILE` is read on every call, so a GitHub App token can be renewed in place.

**Messages the host sends.** `POST /v1/messages/screen` (host secret): before an agent host sends an answer, an
acknowledgement or a notice (on GitHub, a chat), it asks the sidecar. A text carrying what looks like a secret, or
one of a held task, is refused; the receipt keeps the text's hash and length, never the text.

**Secrets from files.** `INTENTPLANE_SIDECAR_SECRET_FILE` and `GH_TOKEN_FILE` (Docker secrets).

**Evidence.** In a test deployment of a multi-agent coding host, a fully compromised worker obeying a prompt
injection had 0 of 13 attacker attempts executed through the gateway, against 13 of 13 without it. With a credible
injected comment mid-task, real models followed it (DeepSeek V4 Pro 3 of 5 times, Claude Haiku 5.5 5 of 5) and the
gateway refused each write. The reproduction kit will be published once the host's maintainers have had time to
address what it shows.

Compatibility: nothing of 0.7.0 changes (the MCP server, the packs, the approval page); the sidecar is new.
`branch.push` is in both default scopes, and in the catalog only when `[git]` is configured.
