## intentplane 0.5.0: put the gateway in front of any MCP agent

`intentplane-mcp` sits between an MCP client (Claude Desktop, Claude Code, Cursor, ...) and the MCP servers it
uses, without changing either. Every call to a configured tool is decided by intentplane first: its critical
arguments (payee, amount, recipients) are resolved against a signed mandate and the user's registries, a Cedar
policy decides, a step-up is confirmed by the user through MCP elicitation, and only then is the downstream tool
called, with the trusted values.

```bash
pip install "intentplane[mcp]"
intentplane-mcp --config intentplane.toml
```

### New
- **MCP proxy** (`intentplane-mcp`), configured in TOML: critical arguments and their trusted sources, the
  parameters the policy needs (amounts scaled to integers for Cedar), passthrough for read-only tools. Unlisted
  tools are hidden from the agent and refused. Receipts are appended to a JSON-lines file.
- **Demo** in `examples/mcp/`: a naive bank-and-mail MCP server whose inbox holds a "we changed banks" email.
- Since 0.4: AgentDojo workspace pack, list-valued critical parameters, write-ahead receipts, an extended
  evaluation (AgentDojo's built-in defenses as baselines, three models, gateway-aware attacks, noisy approvers,
  ablations, incomplete registries).

### Fixed
- `Gateway(..., ledger=...)` replaced an **empty** ledger passed to it by a new one (an empty `Ledger` is falsy),
  so receipts never reached the ledger you gave it.

### Limits of this version
One mandate per proxy session, registries as JSON files, four-eyes not grantable from the same client, and a
step-up needs a client that supports MCP elicitation (otherwise the operation is refused). Research prototype.

59 tests, including the proxy end to end over MCP; every Cedar policy is covered by mutation testing.
