## intentplane 0.5.3: say why an operation was not confirmed

When an operation needs the user's confirmation and the MCP client cannot ask for it (no MCP elicitation, as in
some desktop clients today), the agent is now told exactly that, instead of "the user did not confirm":

> Blocked by intentplane: this operation needs the user's confirmation, but this MCP client cannot ask for it
> (it does not support MCP elicitation); nothing was executed.

The proxy checks the capabilities the client declared when it connected, and falls back to the same answer if
the request fails. A user who declines is still reported as "the user did not confirm the operation". In every
case, nothing executes without a confirmation.

Also: the tool descriptions the agent sees now explain the guard in plain words (critical arguments must match
trusted data, refused calls return the reason, some operations ask the user to confirm), and the demo server's
tools document their side effects, units and formats.
